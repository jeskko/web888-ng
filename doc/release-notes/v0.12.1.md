Safe mode: web888d can run its pages without the radio, so a unit whose
system keeps failing to start stays reachable. Nothing else changes from
v0.12.0.

* **`web888d serve --safe`** runs the web and admin pages (settings,
  logs, OS updates) and touches no hardware: a silent simulated radio
  stands in, and skimmers, uploads (PSKReporter, WSPRnet), live DX spots
  and HPSDR stay off whatever the configuration says.
* **The pages say so:** a "Safe mode" notice with the reason. On the
  admin page it has a **Leave safe mode** button (on the web888-ng-os
  card image: the unit reboots into the normal system).
* **API:** `GET /api/safe` (`{"safe": true, "reason": "..."}`), `POST
  /api/admin/safe/leave` (admin).
* The web888-ng-os card image starts web888d this way from os v0.9.3,
  when neither root slot has tries left or `web888.txt` says
  `safe = yes` (its `docs/safe-mode.md`). Without that image nothing
  starts safe mode by itself.

Tested: unit tests; the notice in headless Chromium (desktop and a
phone-sized screen, the listener and admin pages); in the emulator on a
web888-ng-os build with this code: safe mode from `web888.txt` and from
the boot loader, and out of it again. Not yet run on a Web-888.
