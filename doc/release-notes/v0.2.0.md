Multi-user (milestone M3, `doc/m3-multi-user.md`):

* **Shared receiver**: web users and HPSDR clients share the RX channels
  through leases (classes, quotas, optional pre-emption). Users beyond
  the channel count queue with the waterfall only, and can listen along
  with users who share their frequency (markers on the scale, opt-out
  per user). Same waterfall views share one capture; more distinct views
  than WF slots are time-shared. One DSP worker pool per CPU, with load
  shedding.
* **DSP**: AM carrier AGC, SSB/CW AGC speeds, noise blanker, noise
  reduction, squelch.
* **Configuration file** (`/etc/web888d/web888d.toml`, `--config`;
  hot reload; every option has a key).
* **Passwords and admin**: `web888d passwd` (or `/boot/web888d-admin`),
  an optional listener password (a private receiver), admin pages at
  `#/admin` (status, sessions + kick, configuration form, passwords),
  admin JSON API, Prometheus metrics (`[web] metrics`).
* **WebSocket protocol 2** (v1 clients are refused).
* iq backend (HackRF / recordings): untuned channels cost nothing.

On the A9 (measured with `crates/dsp/examples/bench.rs` on a unit, not a
full server run): the audio chain is 3.5-6 % of a core per user; a
waterfall view costs 13-55 % of a core depending on the FFT budget
(default 6 FFTs per line on 32-bit ARM).
