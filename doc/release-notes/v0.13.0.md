Operations for running a receiver unattended: logs and a settings backup
on the admin page, the card's boot loader from the Update tab, the
bitstream setting that works, and audio gaps that listeners can see.

* **Logs** (admin page): the last lines of web888d's log, the whole
  system's log for this boot, the kernel's, and the card's
  `web888-setup.log`, refreshed, with a filter and a download. Also in
  safe mode. API: `GET /api/admin/logs?source=web888d|boot|kernel|setup`.
* **Settings backup** (Configuration, **Backup**): one JSON file with the
  configuration (passwords as their hashes: keep it private) and the own
  frequency labels; **Restore from a file** checks the whole file before
  writing anything. API: `GET /api/admin/backup`, `POST
  /api/admin/restore`.
* **The card's boot loader** (Update, **Boot loader**, on web888-ng-os
  v0.10.0 and later): whether the card has the running system's
  `BOOT.BIN` and `u-boot.img`, and **Write it to the card** when you ask.
  It has no second copy to fall back to: be prepared to re-image the card
  if something unexpected happens (os `docs/updates.md`).
* **The bitstream:** `[radio] bitstream = "auto"` (the default) now takes
  the image's channelizer for the band when the image has it; the new
  `"standard"` is what `auto` was. With web888-ng-os v0.10.0 the admin
  page's setting takes effect (before, the image's command line always
  overrode it).
* **Audio gaps from overruns:** when web888d falls behind the hardware's
  RX ring, the lost frames now show as a gap in every listener's audio
  (the status bar's "gaps"), and count in `rx_lost_frames`
  (`/api/status`, the admin page's Radio card, `web888d_rx_lost_frames_total`).
* The admin page's tabs scroll sideways on a phone.

Tested: unit and integration tests (backup and restore over HTTP, the
overrun gap, the logs and boot loader commands with stand-ins); the new
pages in headless Chromium (desktop and phone); in the emulator on a
web888-ng-os build with this code: the channelizer loaded by default, the
boot loader written, its old copy kept, and the unit booting with it.
Not yet run on a Web-888.
